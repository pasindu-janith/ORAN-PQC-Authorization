# Chunk 0 — Prerequisites and project skeleton

> Part of the hand-build guide for the post-quantum xApp authorization framework.
> Run the commands in order. Each chunk ends with a check that must pass before the
> next one starts. Nothing here is automated: you type it, you verify it.


**Goal:** Go 1.27, the project layout, and the single configuration file everything
else is derived from.

**Needs the cluster?** No.

---

## 0.1 Inventory the node

Read-only. Record the output; later chunks depend on what is already installed.

```bash
echo "--- go ---"; which go || echo none; echo "--- docker/ctr ---"; which docker ctr; echo "--- registry ---"; curl -s -m 3 http://127.0.0.1:5000/v2/_catalog || echo "no local registry"; echo "--- chartmuseum ---"; curl -s -m 3 http://localhost:8090/health || echo "no chartmuseum"; echo "--- dms_cli/helm ---"; which dms_cli helm; echo "--- openssl ---"; openssl version; echo "--- disk ---"; df -h / | tail -1
```

What matters later:

| Finding | Used by |
|---|---|
| local registry on `127.0.0.1:5000` | Chunk 10 (onboarded xApp images) |
| ChartMuseum missing | Chunk 10 starts it; `dms_cli` pushes charts to it |
| `dms_cli`, `helm` present | Chunk 10 |
| OpenSSL 1.1.1 | the reason the ML-DSA PKI is generated by a Go tool (Chunk 1) |

## 0.2 Install Go 1.27

Required: `crypto/mldsa`, `crypto/mlkem` and `crypto/hkdf` are standard library only
from Go 1.27. Nothing in this project builds on an older Go.

```bash
mkdir -p ~/tools && cd ~/tools && curl -fsSLO https://go.dev/dl/go1.27.1.linux-amd64.tar.gz
```

```bash
cd ~/tools && tar -xzf go1.27.1.linux-amd64.tar.gz
```

```bash
echo 'export PATH=$HOME/tools/go/bin:$PATH' >> ~/.bashrc && export PATH=$HOME/tools/go/bin:$PATH
```

```bash
go version
```

Must print `go version go1.27.1 linux/amd64`.

## 0.3 Create the project skeleton

> **Correction applied.** The first version of this step created `ca/cmd` but not
> `ca/cmd/pki-gen`, and `cat >` cannot create missing parent directories — which
> produced `No such file or directory` when writing files, and then
> `stat .../ca/cmd/pki-gen: directory not found` from `go build`. This command
> creates **every** directory the whole guide needs, up front.

```bash
mkdir -p ~/pqc-xapp-auth && cd ~/pqc-xapp-auth && mkdir -p config internal/{jose,pki,netx,config,logx,smo,pqbind} ca/{enroll,k8s,scripts} ca/cmd/{pki-gen,ric-ca,smo-sim} keycloak/k8s xapp-client xapp-resource pqshim/cmd/pq-shim pqshim/k8s sidecar/{pqtunnel,cmd} sidecar/cmd/xapp-sidecar demo-xapp/cmd/xapp demo-xapp/k8s cmd/methodrun test/cmd/sectest bench/cmd/bench deploy/kyverno xapps build scripts out/{bin,pki,rendered,secrets}
```

```bash
cd ~/pqc-xapp-auth && go mod init github.com/oran-ricsec/pqc-xapp-auth
```

One dependency, and only one. `jwx` is the JOSE library that implements RFC 9964
(ML-DSA inside JWTs); everything else is the standard library.

```bash
cd ~/pqc-xapp-auth && go get github.com/lestrrat-go/jwx/v4@v4.5.0
```

## 0.4 The configuration file

Every hostname, port, subject name, lifetime and algorithm in the project comes from
this one file. Nothing is hard-coded anywhere else.

> **Correction applied.** `KEYCLOAK_HEAP` is now **quoted**. Unquoted, bash assigned
> `-Xms256m` and then tried to execute `-Xmx512m`, printing
> `-Xmx512m: command not found` on every `source`. The derived URLs and
> `KEYCLOAK_NAMESPACE` are also included here rather than appended in later chunks,
> so this file is written once and never edited.

```bash
cat > ~/pqc-xapp-auth/config/env.sh <<'EOF'
# Single source of configuration. Source it before any command:
#   set -a; source ~/pqc-xapp-auth/config/env.sh; set +a

# --- Kubernetes -------------------------------------------------------------
RICSEC_NAMESPACE=ricsec
XAPP_NAMESPACE=ricxapp
CLUSTER_DOMAIN=cluster.local
IMAGE_TAG=0.1.0

# --- Identity / PKI ---------------------------------------------------------
ORG=O-RAN-RIC
XAPP_OU=xApps
ROOT_CA_DAYS=3650
INTERMEDIATE_CA_DAYS=1825
SERVER_CERT_DAYS=365
BOOTSTRAP_CERT_VALIDITY=24h

# --- RIC intermediate CA (the enrollment service, Chunk 3) ------------------
RIC_CA_SERVICE=ric-ca
RIC_CA_PORT=8443
CA_DEFAULT_LEAF_LIFETIME=24h
CA_MIN_LEAF_LIFETIME=5s
CA_MAX_LEAF_LIFETIME=720h
# Method A = long-term identity; Method B = ephemeral. Same code, different lifetime.
LONGTERM_CERT_LIFETIME=168h
EPHEMERAL_CERT_LIFETIME=15m

# --- Keycloak ---------------------------------------------------------------
KEYCLOAK_SERVICE=keycloak
KEYCLOAK_PORT=8443
KEYCLOAK_REALM=ric-realm
ACCESS_TOKEN_LIFESPAN=300
# The namespace of any pre-existing Keycloak. The PKI issues a server certificate
# valid for BOTH this namespace and RICSEC_NAMESPACE, so the Chunk 4 decision
# (reuse the existing Keycloak, or run a dedicated one in ricsec) needs no new PKI.
KEYCLOAK_NAMESPACE=keycloak
# A pinned version, never ':latest' - a moving tag silently changes the server
# under you and can lose the realm. 26.6.0 also guarantees DPoP support (Method C).
KEYCLOAK_IMAGE=quay.io/keycloak/keycloak:26.6.0
# MUST be quoted: this value contains a space, and env.sh is sourced by bash.
KEYCLOAK_HEAP="-Xms256m -Xmx512m"

# --- Authorization ----------------------------------------------------------
TOKEN_AUDIENCE=ric-xapps
TOKEN_SCOPE=ric-sdl-access
REQUIRED_ROLE=ric-sdl-access

# --- Demo xApps (Chunk 6) ---------------------------------------------------
XAPP_PORT=8443
XAPP_A_NAME=xapp-a
XAPP_A_METHOD=A
XAPP_A_CLIENT_ID=xapp-longterm
XAPP_B_NAME=xapp-b
XAPP_B_METHOD=B
XAPP_B_CLIENT_ID=xapp-ephemeral
PEER_INTERVAL=30s

# --- Post-quantum (Chunks 7-9) ---------------------------------------------
PQ_MODE=false
PQ_ISSUER=shim
PQ_SHIM_SERVICE=pq-shim
PQ_SHIM_PORT=8443
PQ_SIGNING_ALG=ML-DSA-65
PQ_IDENTITY_KEY_ALG=ML-DSA-65
PQ_DPOP_ALG=ML-DSA-44
PQ_ROOT_ALG=ML-DSA-87
PQ_CA_ALG=ML-DSA-65
PQ_SERVER_ALG=ML-DSA-65
PQ_KEX_ONLY=true
PQ_TOKEN_LIFETIME=300s

# --- Derived (computed from the values above; keep this block last) ----------
KEYCLOAK_HOST=${KEYCLOAK_SERVICE}.${RICSEC_NAMESPACE}.svc.${CLUSTER_DOMAIN}
KEYCLOAK_URL=https://${KEYCLOAK_HOST}:${KEYCLOAK_PORT}
TOKEN_ISSUER=${KEYCLOAK_URL}/realms/${KEYCLOAK_REALM}
RIC_CA_HOST=${RIC_CA_SERVICE}.${RICSEC_NAMESPACE}.svc.${CLUSTER_DOMAIN}
RIC_CA_URL=https://${RIC_CA_HOST}:${RIC_CA_PORT}
PQ_SHIM_HOST=${PQ_SHIM_SERVICE}.${RICSEC_NAMESPACE}.svc.${CLUSTER_DOMAIN}
PQ_SHIM_URL=https://${PQ_SHIM_HOST}:${PQ_SHIM_PORT}

# --- Derived: which service issues the token the validators will trust -------
# In the reference project these came from a Makefile conditional. This guide has no
# Makefile, so they are computed here - which is why env.sh is *sourced*, not parsed.
#   PQ_MODE=false              -> Keycloak issues the token the resource validates
#   PQ_MODE=true, shim         -> the pq-shim re-issues it, ML-DSA signed   (Chunk 7)
#   PQ_MODE=true, keycloak     -> the authorization server itself           (the exit condition)
if [ "$PQ_MODE" = true ] && [ "$PQ_ISSUER" = shim ]; then
  RESOURCE_TOKEN_ISSUER=${PQ_SHIM_URL}
  RESOURCE_JWKS_URL=${PQ_SHIM_URL}/v1/jwks
  RESOURCE_INTROSPECTION_URL=${PQ_SHIM_URL}/v1/introspect
else
  RESOURCE_TOKEN_ISSUER=${TOKEN_ISSUER}
  RESOURCE_JWKS_URL=${TOKEN_ISSUER}/protocol/openid-connect/certs
  RESOURCE_INTROSPECTION_URL=${TOKEN_ISSUER}/protocol/openid-connect/token/introspect
fi
# The RIC CA presents an ML-DSA server certificate in post-quantum mode.
if [ "$PQ_MODE" = true ]; then
  RIC_CA_SERVER_CERT=ric-ca-server-pq
else
  RIC_CA_SERVER_CERT=ric-ca-server
fi
EOF
```


Load it. You will do this in every new shell:

```bash
cd ~/pqc-xapp-auth && set -a; source config/env.sh; set +a; echo "ORG=$ORG  KEYCLOAK_URL=$KEYCLOAK_URL  HEAP=[$KEYCLOAK_HEAP]"
```

No error should appear, and `HEAP` must show both flags.
